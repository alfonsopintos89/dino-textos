# fechita

Fechas en JavaScript, sin que se te vaya la tarde. Inmutable y con zonas horarias de verdad.

```bash
npm install fechita
```

## Por qué

El `Date` nativo arrastra decisiones de 1995. Los meses empiezan en cero, `getYear()` devuelve años de dos dígitos, y cualquier método que arranque con `set` te modifica el objeto que ya tenías guardado en otra variable. Se puede trabajar así. Lo pagás en bugs de fin de mes, cuando alguien suma treinta días y aterriza en marzo.

Si tu runtime ya tiene `Temporal`, usá `Temporal`. Esta librería existe para los proyectos que todavía no lo tienen y no quieren esperar.

## La idea

Un objeto de fechita no cambia nunca. Cada operación devuelve uno nuevo.

```js
import { fecha } from 'fechita'

const hoy = fecha('2026-03-14T10:30', 'America/Argentina/Buenos_Aires')
const manana = hoy.mas({ dias: 1 })

hoy.iso()     // '2026-03-14T10:30:00-03:00'
manana.iso()  // '2026-03-15T10:30:00-03:00'
```

`hoy` sigue siendo el 14. Siempre.

Lo mismo con `menos`, `empiezoDe` y `finDe`:

```js
hoy.menos({ semanas: 2 })
hoy.empiezoDe('mes')   // 2026-03-01T00:00:00-03:00
hoy.finDe('semana')    // domingo, salvo que configures otra cosa
```

## Zonas horarias

Toda fecha lleva su zona adentro. No hay estado global que alguien te pise desde otro módulo.

```js
const reunion = fecha('2026-07-02T09:00', 'America/Montevideo')

reunion.en('Europe/Madrid').formato('HH:mm')  // '14:00'
reunion.en('UTC').iso()                       // '2026-07-02T12:00:00Z'
```

Los offsets salen de `Intl`, así que el horario de verano lo resuelve el navegador con la base de datos que ya tiene. Cuando una hora no existe (las 2:30 de una madrugada en la que el reloj salta de 2 a 3), fechita tira `HoraInexistente` en vez de elegir por vos. Es molesto. Es mejor que un turno médico agendado en una hora que no pasó nunca.

## Parseo

```js
fecha('2026-03-14')                      // ISO, lo más seguro
fecha('14/03/2026', { formato: 'DD/MM/YYYY' })
fecha(1773489000000)                     // timestamp
fecha(new Date())                        // un Date nativo
```

No adivina. Un string que no matchea el formato que le pasaste devuelve una fecha inválida, y `esValida()` te lo dice. Si querés que reviente, `fecha.estricta()` tira.

## Formato

```js
hoy.formato('D [de] MMMM [de] YYYY')  // '14 de marzo de 2026'
hoy.formato('dddd')                   // 'sábado'
hoy.relativa()                        // 'hace 3 horas'
```

Los nombres de meses y días salen de `Intl.DateTimeFormat`, con `es-AR` por defecto. Para cambiarlo, `fecha.local('es-ES')` o el locale que necesites.

## Diferencias

```js
const inicio = fecha('2026-01-01')
const fin = fecha('2026-03-14')

fin.diferencia(inicio, 'dias')   // 72
fin.diferencia(inicio)           // { meses: 2, dias: 13 }
```

La diferencia en meses cuenta meses calendario, no bloques de 30 días. Del 31 de enero al 28 de febrero hay un mes, aunque haya 28 días en el medio.

## Comparar

```js
a.antesDe(b)
a.despuesDe(b)
a.mismo(b, 'dia')       // mismo día, sin importar la hora
a.entre(desde, hasta)
```

## Lo que no hace

No tiene calendarios no gregorianos. No hace aritmética de días hábiles ni sabe de feriados, porque los feriados son un problema de tu país y de tu convenio, no de una librería de fechas. No parsea texto libre tipo "el martes que viene".

## TypeScript

Los tipos vienen en el paquete. Las unidades (`'dias'`, `'meses'`, `'horas'`) son literales, así que un typo te lo marca el editor antes de correr nada.

## Tamaño y navegadores

Pesa [falta dato] kB minificado y comprimido, sin dependencias. Necesita `Intl` con soporte de `timeZone`, que está en todo lo que no sea IE.
